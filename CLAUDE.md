# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Wave** is a local-first, Mac-native **text-based audio editor for podcasts** — edit audio by editing its transcript (à la Descript). It is a [Tauri v2](https://tauri.app/) desktop app: a React/TypeScript frontend and a Rust backend communicating over IPC. Transcription runs entirely on-device via `whisper-rs` (whisper.cpp) on the Apple Silicon GPU.

- **Identifier:** `com.mskayyali.wave`
- **Window:** 1280×820, min 960×600, size and position remembered (`tauri-plugin-window-state`). The title bar is hidden (`titleBarStyle: Overlay`), and the window buttons stay where macOS puts them: a 28 pt band at the top left. `trafficLightPosition` isn't used, because Tauri applies it while the window is still hidden and macOS resets it on show. Wave's top edge is laid out around the band (`--wave-titlebar-height`, `--wave-titlebar-inset`):
  - the sidebar's logo row is the band, the logo centred on the buttons;
  - Projects and Settings start with the sticky `.wave-titlebar` strip;
  - the editor has `.wave-window-band` above its top bar;
  - in full screen the bands collapse.

  The app and its wordmark are "Wave". Fraunces (SIL OFL, `@fontsource-variable/fraunces`, all axes, bundled) is the brand face (`--wave-font-display`): the wordmark, the page titles and the welcome. The UI stays IBM Plex.
- **Platform:** macOS 13.4+ on Apple Silicon (the `whisper-rs` `metal` feature ties transcription to Metal; ONNX Runtime's prebuilt library needs 13.4)
- **Status:** MVP complete through Phase 35 — see [PLAN.md](PLAN.md) for the full feature history.

## Commands

> **Environment note:** Node is at `/opt/homebrew/bin/node` and `bun`/`cargo` aren't on the default shell PATH. Either prefix with the full path or run `export PATH="$HOME/.cargo/bin:/opt/homebrew/bin:$PATH"` first. The package manager is **bun** (`bun.lock` is the lockfile; there is intentionally no `package-lock.json`). The preview server is configured in `.claude/launch.json`.

### Development

```bash
# Frontend dev server only (port 1420)
/opt/homebrew/bin/node node_modules/.bin/vite     # or: bun run dev

# Full Tauri app in dev mode (requires Rust toolchain)
bunx tauri dev
```

### Build & checks

```bash
bun run build          # tsc type-check + vite build (frontend)
npx tsc --noEmit       # type-check only
bunx tauri build       # package the desktop app (Wave.app, arm64, macOS 13.4+)
cargo check            # Rust check (run from src-tauri/)
```

> No lint or test tooling is currently configured. Rust dev tests that need real audio or models are `#[ignore]`d and take paths from env vars (e.g. `projects::tests::import_speed`, `transcription::tests::transcribe_file`, `speakers::tests::diar_parity`); each documents its command.
>
> Dev builds are optimised (`Cargo.toml`: dependencies at opt-level 3, Wave's crate at 1), so audio and model code runs near release speed in `tauri dev`. Editing a Rust file while `tauri dev` runs rebuilds and **restarts the app**, which interrupts any import, transcription or analysis in progress.

## Architecture

```
Frontend (React/TS/Vite) ←── Tauri IPC (invoke) ──→ Backend (Rust)
```

### Backend — `src-tauri/src/`

Rust library crate (`wave_lib`). `lib.rs` wires up `tauri::Builder`, registers the `opener` and `dialog` plugins, manages the `DownloadManager` state, and registers all command handlers. Commands are split by domain:

- **`lib.rs`** — app setup, plugin/handler registration; `save_text_file` command.
- **`models.rs`** — model lifecycle. `list_models`, `start_model_download` (streaming, resumable, cancellable), `cancel_model_download`, `delete_model`. `KNOWN_MODELS` lists a `ModelSpec { id, filename, url }` per model, downloaded into `{app_data}/models/` (`.part` while in flight). Four models ship: the transcriber `large-v3-turbo` (whisper.cpp GGML — chosen for accurate words *and* word timings; any re-added Whisper model also needs a DTW preset in `dtw_preset_for` and a `MODEL_CATALOG` entry in `src/lib/modelCatalog.ts`) and the English aligner `wav2vec2-align-en` (wav2vec2-base-960h int8 ONNX, ~91 MB, Apache-2.0). The UI ships those two as one required **Transcription** download (see `TRANSCRIPTION_BUNDLE`), but Rust still treats the aligner as optional (`aligner_path()` returns it when downloaded), so older installs and non-English audio still transcribe. Then speech enhancement's clean-up `dpdfnet` (DPDFNet by Ceva, `dpdfnet8_48khz_hr`, 14 MB, Apache-2.0 code and weights, pinned to Hugging Face revision dd6818d); `installed_model_path(app, id)` finds it. Clear and Uhm (Desert Ant Labs) were removed for open-sourcing (their licence isn't open source; DPDFNet measured better than Clear): `remove_retired` deletes their downloads at launch. Last, the speaker detector `nemotron3-diarization` (NVIDIA Nemotron 3 Diarization, OpenMDW 1.1; the onnx-community int8 export pinned to commit 353b6f8, 115 MB). It is two files in its own folder: the weights (`model_quantized.onnx_data`, the main file) and the graph that loads them from beside it, a **companion**. `ModelSpec.companions` are small files fetched before the main one, needed for Ready and deleted with it; `diarization_model_path()` returns the graph.
- **`projects.rs`** — project CRUD, audio import, edits persistence, export. `remove_leftovers` runs once at launch (from `lib.rs` setup) and deletes what nothing reads any more: `peaks.json`, `preview_*.wav` and interrupted `.part` writes. `create_project`, `list_projects` (repairs stale `importing`/`transcribing` state on launch), `rename_project`, `delete_project`, `import_audio` (symphonia decode → rubato resample → hound 16 kHz WAV; the same decode pass builds `waveform.bin`), `get_audio_path`, `get_playback_audio_path`, `load_edits`/`save_edits`, `export_audio` (decodes `audio_original.*` and splices at native rate/channels via `splice`/`write_spliced`: zero-crossing snap + 8 ms equal-power crossfade, and added pauses (`InsertOp`) as looped room tone; no FFmpeg; with `enhanced: true` it splices the enhanced WAV instead; it falls back to `audio_16k.wav` only when the original can't be decoded). It writes `format` (`encode::ExportFormat`, 16-bit WAV when left out) through `encode.rs`, and sends `export:progress` (`ExportProgress`: reading, then writing, as one 0–1, at most once a percent). `decode_window_mono` decodes just a stretch, seeking first (the enhancement preview).
- **`transcription.rs`** — `transcribe` (async; emits progress events), `get_transcript`, and `realign_transcript` (re-times an existing transcript's words in place; same words, so saved edits stay valid). Pipeline: `speech_chunks` gives Whisper the audio in pieces of at most 30 s cut in pauses, leaving out silences of 2 s or more (10 dB under the speech threshold, less 300 ms either side), where Whisper invents words → the language from the first three pieces (`detect_language`), then held → whisper-rs on each piece as `Decoding::default()` says: beam search (5) and, for English, `FILLER_PROMPT`, a prompt written the way people talk, so Whisper writes the fillers it hears; **DTW token timestamps** (model preset) → words assembled from Whisper’s leading-space boundaries (punctuation attaches to the previous word) → `refine_with_vad`, an energy VAD with an adaptive threshold that snaps word starts to speech onsets and trims word ends through silence → for English with the aligner downloaded, **CTC forced alignment** (`alignment.rs`) then a second, gentler VAD pass (`ALIGNED_SNAP`: only moves starts earlier, never into the previous word). Detected language is stored in `transcript.json`. On a 21-minute AMI meeting against its hand transcript, the pieces, beam and prompt took words wrong from 36.9 % to 25.0 % and fillers written from 19 % to 68 %, with no repetition loops (there were 7); the table is on `Decoding`. Tests: `pieces_are_cut_in_pauses`, `long_silences_are_left_out`; `transcribe_file` (ignored) runs a WAV through it all, with `PROMPT`, `BEAM` and `WHOLE` for experiments.
- **`alignment.rs`** — `align_words`: wav2vec2 CTC forced alignment via ONNX Runtime (`ort`), the WhisperX approach. Splits the words into ~15 s chunks at pauses, runs the model on each audio window, and Viterbi-aligns the words' letters (numbers and symbols spelled out first) to get a start/end per word; words with nothing alignable are interpolated.
- **`enhance.rs`** — speech enhancement, written for Wave: decode and resample to 48 kHz mono (`decode_48k`), then three steps, each the user's choice: `clean_up` (DPDFNet, then the clean-up strength as a plain mix with the original; both are sample-aligned), `shape` (the EQ preset, eq.rs) and `level` (the loudness target, master.rs: one gain capped at +24 dB, enough to bring a −43 LUFS recording to −19, true peak under −1.5 dBTP). `EnhanceOptions.models` is `dpdfnet` | `none`; runs saved by earlier versions may say `clear` or `both` (or nothing: read as `clear`) and still play, but `checked` refuses to run them ("Clear is no longer part of Wave"), and refuses an unknown EQ preset or a run with nothing to do. Commands: `enhance_audio` (emits `enhance:progress` with a phase), `preview_enhancement` (15 s through the same steps from 4 s earlier, written as `preview_enh_*` beside the untouched stretch at the same loudness; decodes only that stretch with `decode_window_mono`), `cancel_enhance`, `get_enhancement`, `set_enhancement_enabled`, `remove_enhancement`; state in `enhance.json` (`model` names what ran, e.g. `dpdfnet@dd6818d+eq:brighter`). Tests: options and old runs; the steps without a model keep time and hit the target. Opt-in on real audio (`DPDFNET_MODEL`, `ENHANCE_IN`): `stays_in_step` (every strength and EQ: same length, zero offset at eight points, so the strength mix can't comb-filter and edits apply to both versions), `clean_up_yardstick` (SI-SDR and noise left in pauses with hiss and room echo mixed in: DPDFNet takes 40–51 dB out of the pauses), `preview_window`, `real_audio` (about 6× real time in a debug build).
- **`dpdfnet.rs`** — DPDFNet, the streaming ONNX graph: one STFT frame per call (Vorbis 960/480, unscaled: the graph applies 1/960 and 960 itself), `spec` [1,1,481,2] + `state_in` → `spec_e` + `state_out`, the initial state being zeros plus the `erb_norm_init`/`spec_norm_init` vectors from the model's metadata. Output lags 4 frames (1920 samples). Features, mask and deep filter are all in the graph. A frame takes about 3 ms on one core, so a file is cut into segments (5–30 s, spread over one single-threaded session per core), each fed the 4 s before it and the 200 ms after it, then trimmed. It matches the reference implementation's output to 53 dB (`tests::matches_the_reference`) and runs about 10× real time on an M3 Pro. It's written from Ceva's own reference (`infer_dpdfnet_onnx.py`, Apache-2.0).
- **`master.rs`** — loudness and peaks, written from the public standards: integrated loudness per ITU-R BS.1770-4 (`integrated_loudness`: K-weighting designed from its analogue prototypes, which reproduce the standard's 48 kHz coefficients (tested to 1e-8); 400 ms blocks, 75 % overlap; −70 LUFS absolute and −10 LU relative gates), true peak by 4× oversampling (`true_peak_db`, a 16-tap Hann-windowed sinc per phase), and `limit`: per sample the gain it needs (counting peaks between samples), the lowest over the next 5 ms (a monotonic deque), a running mean over those 5 ms as the ramp (it can't exceed any sample's need), then an 80 ms recovery computed in f64 that settles exactly; no delay, so the result stays sample-aligned. `master` = measure, one capped gain, limit. Tests: the K-weighting coefficients, −3.01 LUFS for a full-scale 997 Hz sine, the gates, an inter-sample peak at 12 kHz, the ceiling, no delay, audio away from peaks untouched, and the target with and without the cap.
- **`eq.rs`** — the EQ presets for spoken voice, each fixing one problem (Riverside's model): `clearer`, `warmer`, `less-boom`, `less-boxy`, `less-nasal`, `brighter`, `less-harsh`, `broadcast`. Each is a short chain of RBJ biquads (high-pass, bells, slope-0.8 shelves) at the usual voice ranges; boosts stay within +3 dB at Medium (+5 at Strong) and are broad, cuts narrower. Warmth is a bell at 150 Hz, not a shelf, so the rumble the high-pass removes isn't lifted again for the limiter to pay for. `amount_scale`: Subtle ×0.5, Medium ×1, Strong ×1.5 on every gain; Less boom's high-pass also rises with it (80/100/120 Hz). Brighter, Less harsh and Broadcast end with `de_ess`: a zero-phase split at 4.5 kHz (so untouched audio comes back exactly), the high band turned down by up to the step's dB where it holds 40–80 % of the energy, the gain smoothed both ways. On the Sample, Brighter lifts voiced speech above 7 kHz by about 2 dB while S sounds stay put; Less harsh takes S sounds down 3–4 dB and leaves voiced speech alone. `apply` takes the whole stretch. Tests cover each preset's curve, the limits, and the de-esser on voice and hiss.
- **`encode.rs`** — the exported audio in the chosen format (`ExportFormat`: `wav`/`flac` with `bits` 16 or 24, `mp3`/`aac` with `kbps` and `mono`; `checked` refuses anything the presets don't offer). WAV with hound; AAC (.m4a, AAC-LC) and FLAC with macOS's own encoders through AudioToolbox's ExtAudioFile (hand-written FFI in `core_audio`, constants checked against the SDK headers: float PCM in, the bit rate nearest the asked one that the encoder offers, quality max, then `'accf'` set to NULL so the settings take); MP3 with LAME (`lame.rs`). MP3 and AAC take the source rate if they can (`lossy_rate`, else the nearest: 96 kHz becomes 48 kHz) and one or two channels (`fold`: a mono preset averages; more than two fold to even/odd). The file is written as a hidden `.name.part` beside the destination and renamed when complete. Tests decode every format back (FLAC bit-exact; AAC and MP3 match their input to 20+ dB at the encoder's delay; MP3 128 kbps is CBR with LAME's Info tag); `tests::real_audio` (ignored, `EXPORT_IN`) times each on a real file: on the 97 s Sample, MP3 runs 120–145× real time, AAC 180–450×, FLAC 600×. macOS's m4a keeps a 56 KB `free` box ahead of the audio for its index (fast start).
- **`lame.rs`** — MP3 with LAME 3.100, loaded at run time with `libloading` (17 functions, resolved once into `Lame`) from `Contents/Frameworks/libmp3lame.0.dylib` beside the executable, or in a debug build `vendor/lame/`: a separate library, as the LGPL asks. CBR, quality 2, joint stereo, ID3 off, and LAME's Info tag (delay and padding, so players trim them) written over the first frame after the flush. Mono goes through the planar call: the interleaved one assumes two channels.
- **`speakers.rs`** — speaker detection: `detect_speakers` (emits `speakers:progress`), `get_speakers`, `save_speakers` (names, show); results in `speakers.json` as per-speaker segments. The ONNX file is one step of a Streaming Sortformer (features + cached context in, per-10 ms logits + the chunk's encoder frames + the silence embedding out), so the module ports the rest of transformers' `Nemotron3DiarizationForAudioFrameClassification` (offline mode). Features: pre-emphasis 0.97, 512-point STFT of a 400-sample Hann window every 10 ms (centred), 128 Slaney mel bands (sparse), ln(x + 2⁻²⁴), the padding frame masked. Chunks of 340 encoder frames (8 mel frames each) with 40 of look-ahead attend to the Arrival-Order Speaker Cache (264 frames) and a 40-frame FIFO. On overflow, 300 frames move to the cache, which is compressed by the AOSC score policy (`compress`, `frame_scores`, `boost`). It matches the reference to 99.975% of frame decisions on a 42-minute episode (`tests::diar_parity`) at 76× real time (release).
- **`waveform.rs`** — `get_waveform_overview` gives a project card its miniature (the loudest peak per stretch, from `waveform.bin`, or none). Also the waveform the editor draws, computed natively so it appears at once. `WaveformBuilder` takes interleaved samples in pieces (fed by `import_audio`'s decode) and writes `waveform.bin`: a 28-byte `WVF1` header, then a 1 ms [max, min] envelope over all channels (i16, windows on absolute sample positions) and 10 ms RMS energy (f32). `get_waveform` returns its path, building it first for projects imported before it existed (1.7 s for a 42-minute MP3 in a dev build).
- **`menu.rs`** — the menu bar: Wave (About Wave, which opens Wave's own `AboutWave` panel rather than the system's box; Settings ⌘,), File (New Project ⌘N, Back to Projects ⌘[), Edit (Undo/Redo ⌘Z/⇧⌘Z, the system's cut/copy/paste/select all, Find ⌘F/⌘G/⇧⌘G), View (Flow ⌘1, Segments ⌘2, full screen), Window, Help (Keyboard Shortcuts ⌘/). Wave's items reach the frontend as a `menu` event with the item id (`src/lib/commands.ts`). WebKit offers each key to the page first, and the menu acts only if the page didn't `preventDefault`. So the editor keeps handling ⌘Z/⇧⌘Z itself, and nothing else in JS handles the menu's other shortcuts, which avoids firing twice.
- **`settings.rs`** — `get_settings`/`set_settings` for `settings.json`: `selectedModelId`, and `agentAccess` (changed only through `set_agent_access`). Writes keep keys Wave doesn't know (`merged`, tested), since the file may hold other keys.
- **`agent.rs`** — AI agents, app side. With agent access on, a Unix socket `{app_data}/agent.sock` (mode 0600, this user only) takes one JSON line per tool call from `wave mcp`. The call is emitted to the frontend as `agent:request` and answered through `agent_reply`, with a 55 s limit (agent apps give up at about 60 s). Also `agent_status` and `set_agent_access`, plus `restore` at launch (listen, or clear a stale socket).
- **`mcp.rs`** — `wave mcp` (`main.rs` checks the first argument): the MCP server agent apps launch, over stdio. It's hand-written: just the handshake (echoes the client's revision when known or newer), ping, `tools/list` and `tools/call`, forwarding each call to the socket. The 22 tools are defined here (`tools()`), so agents see them even while Wave is closed; their behaviour is in `src/lib/agentTools.ts`, so keep the two in step. Tests check the handshake and the tool schemas.

Rust↔frontend types use `#[serde(rename_all = "camelCase")]`.

### Frontend — `src/`

React 19 + Vite. Entry `main.tsx` → `App.tsx`. UI is IBM Carbon (`@carbon/react`, g100 dark theme). Layered structure:

- **`pages/`** — `ProjectsPage`, `SettingsPage`, `EditorPage` (the ~600-line core; owns selection, edit queue, and silence enrichment).
- **`components/editor/`** — `EditorTopBar`, `TranscriptEditor` (TipTap), `WordNode` (custom inline atom node), `SegmentsView`, `WaveformTimeline`, `PlaybackControls`, `InspectorPanel`, `WordContextMenu` (Carbon `Menu`; the right-click menu shared by transcript and waveform), `EnhancePanel` and `EqPanel` (the Speech enhancement and EQ tools in the inspector's **Tools** tab), `ToolCredit` (the provider credit and `ExternalLink`), `SpeakersPanel` (Tools → Speakers: detect, rename, show), `WordCorrection` (the field, under a word, for correcting what transcription misheard), `ShortcutsModal` (the keyboard shortcuts sheet, opened with ? or the top bar's keyboard button; the list lives in `lib/shortcuts.ts`, keep it in sync with the keydown handler). `InspectorPanel` is Carbon `Tabs` (Details, Tools, Edits, Export, each with an icon stacked over its label so four fit at 300 px; the last one shown is saved as `wave.inspectorTab`). The Tools tab is `ToolsTab`: a `ContainedList` per group (Tighten: Pauses; Sound: Speech enhancement, EQ; People: Speakers), a row per tool with its live status and its next step as the row's action (Get, Find, Remove N, Shorten, Enhance, or the enhancement's on/off switch); a running tool shows its animated `JobIcon`. A row opens the tool on its own (a back arrow and its name over its panel; which one is open is kept in `InspectorPanel` while other tabs show). Each panel puts its results first and folds its settings under `ToolOptions` ("Options"). The other tabs are `ContainedList`s. Export's Audio list holds one form: a format switch (MP3 | AAC | WAV | FLAC) with what it's for, its presets as a `wave-choice-list` (Quality), what's being exported with the size for MP3 and AAC, and **Export MP3…** (the save dialog takes the format's extension). The format and a preset per format are remembered (`wave.exportFormat`, `wave.exportPresets`). Its width is dragged from the left edge, or ←/→ on the focused edge: 300–480 px, double-click resets to 320, saved as `wave.inspectorWidth`.
- **`components/editor/`** (this round) — `FindBar` (⌘F, above the text), `ProjectStatus` (the editor before there's a transcript: importing or transcribing with live progress, never transcribed, failed, unreadable, each with its action), `OpenSettings` (tools whose model isn't downloaded).
- **`components/layout/`** (this round) — `DropOverlay` (files dragged over the window), `ErrorBoundary` (a crash screen with Reload, in `main.tsx`), `AboutWave` (a passive Carbon `Modal`, 56rem at most, from the sidebar footer's About and the menu's About Wave, rendered by App so it works over the editor: `BrandHero` (mounted only while open, so it starts from the top), the wordmark and version, what Wave is, six features in two columns, Built by Saleh Kayyali with x.com/mskayyali and mskayyali.com (`ExternalLink`, the system browser), and the speech models it runs on. It fits a 1280×820 window without scrolling). The sidebar footer is About on the left and the version on the right. `BrandHero` makes its SVG ids unique per copy (`useId`): the welcome and About can both be showing, and an animated clip found by a shared id would run on the other's clock. The editor's keys stand down while any `.cds--modal` has focus.
- **`pages/SettingsPage`** — the models as compact rows grouped like the Tools tab (Required: Transcription; Sound: DPDFNet; People: Speaker detection), each `ContainedListItem` with a one-line summary, size, parts, maker and licence, its state (`IconIndicator`) and one action (Download/Resume, Cancel, Retry, or delete); progress and errors under the row. Then AI agents.
- **`components/settings/`** — `AgentAccess` (Settings → AI agents: the switch, and copy-ready setup for Claude Desktop, Claude Code and ChatGPT/Codex built from this executable's path).
- **`components/layout/`** — `AppShell` (sidebar + nav) and `ActivityStatus`, the background-jobs status (see *Background jobs* below), at the foot of the sidebar and in the editor's top bar. `JobIcon` draws what a job is doing as a small animated icon. The shapes are Phosphor Icons (MIT), split into the parts that move; `jobKind` reads the kind from the activity id's prefix, and the motion is in `global.scss` under *Job icons*. A new kind of job needs an id prefix, an entry in `ICONS` and its keyframes.
- **`hooks/`** — one per domain: `useModels`, `useProjects`, `useSettings`, `useTranscript` (also `realign`), `useSpeakers` (detect/rename/show), `useEnhancement` (run/cancel/switch/discard, plus the draft options for the next run), `useWaveform`, `useActivity` (the activity store in React: `useActivities`, `useActivityRunning`/`Progress`/`Detail`, `useActivityEnd`; `useActivityEvents` runs once in App).
  - `useWaveform(audioSrc, { peaks, altSrc, useAlt })` draws at once from the precomputed `peaks` (`lib/waveformData.ts` loads `waveform.bin`): a wavesurfer.js 8 waveform from the 1 ms envelope (accurate to 1000 px/s; Regions plugin for the selection and draggable cut edges; Hover plugin for a time readout) and the 10 ms energy frames, so the editor works before any audio is decoded. The audio then decodes in the background (WebKit's `decodeAudioData`: about 7 s for a 42-minute MP3) into the `EditPlayer`; `audioReady` turns true, and Play pressed earlier waits for it (the button pulses). Without peaks it falls back to decoding first and `analyzeAudio`. It also takes an alternative version of the same audio (`altSrc`, the enhanced file): decoded in the background and, while `useAlt` is on, swapped into the player (`EditPlayer.setBuffer`, which keeps position and play state) and the waveform (`ws.setOptions({ peaks })`). Energy always comes from the original, so cut edges don't move when switching.
- **`lib/editPlayer.ts`** — `EditPlayer`, a gapless player for the *edited* timeline that wavesurfer drives through its `media` option. At 1× each kept segment is an `AudioBufferSourceNode` scheduled on the audio clock with the export's 8 ms crossfade (exact, even with the window in the background). Other speeds use Signalsmith Stretch (pitch-preserving WASM worklet), fed the already-edited signal in chunks. It can start without audio (`hasAudio` false, play waits) and get it later through `setBuffer`; `duration` comes from the waveform until then.
- **`lib/eq.ts`** — the EQ presets as shown (`EQ_PRESETS`: id, name, note; `EQ_AMOUNTS`, `eqName`). Keep the ids in step with `eq.rs` and `mcp.rs`.
- **`lib/audioFormats.ts`** — the audio export formats and presets (`AUDIO_FORMATS`: MP3, AAC, WAV, FLAC, each with a note and presets with the settings Rust takes), `findPreset` (a preset id, or a format's standard one), `PRESET_IDS` and `estimateMb`. The agents' `export_audio` takes the same ids; keep them in step with `encode.rs` and `mcp.rs`.
- **`lib/pauses.ts`** — the Pauses tool's logic: `findPauses`, `RHYTHMS`, `shortenPauses`, `findRoomTone`, and `editedTime` (original → edited time, for exports).
- **`lib/speakers.ts`** — `assignSpeakers` gives each word the speaker it overlaps most (else the nearest within 1 s, else the previous word's), the speaker palette and `SpeakerLabels` (speaker per `enrichedWords` index + names).
- **`lib/commands.ts`** — the menu's commands: a screen registers handlers while it's showing (the newest runs first; returning false passes it on). `typing()` says when a text field has the keyboard, so Undo/Redo then use the field's own (`document.execCommand`). **`lib/navigation.ts`** — `openSettings` from deep in the editor. **`lib/textSearch.ts`** — `findPhrase`, shared by Find and the agents' `find_text`.
- **`lib/agent.ts`** — what an editor exposes to AI agents (`EditorAgentApi`, `AgentWord`), the registry of the open editor (`registerEditor`, `openEditor`, `waitForEditor`) and `agentName` ("Claude", "Codex"…). **`lib/agentTools.ts`** — the tools (`runTool`): reading (transcript as numbered lines, words, find, pauses), editing (cut words or time, restore, correct, shorten pauses by a length or to a rhythm, add pauses, rename a speaker, undo), the sound (`enhance_audio`: clean-up, EQ preset and amount, loudness, merged over what's applied; `use_enhanced_audio`), analysis, export and import. `get_project` reports long and added pauses and the enhancement. **`hooks/useAgent.ts`** — `useAgentBridge` in App: answers `agent:request`, can open and import projects.
- **`lib/activity.ts`** — the activity store: every background job (`start`/`update`/`finish`/`dismiss`, `track` around a promise), outside React so a job outlives the editor that started it.
- **`lib/waveformData.ts`** — `loadWaveform` (via `get_waveform`) and `parseWaveform` for `waveform.bin`.
- **`lib/followWord.ts`** — keeps the playing word in view a page at a time: scrolls only when it leaves the middle 10–85 % of the transcript, then puts it a third of the way down.
- **`lib/audioAnalysis.ts`** — `analyzeAudio` (draw envelope + energy) and `quietestPoint`, used to ease a cut's edge to a nearby quieter moment.
- **`lib/modelCatalog.ts`** — frontend-only display metadata for models (Rust knows only ids/filenames); `kind` separates transcription models from the aligner. `TRANSCRIPTION_BUNDLE` groups Whisper and the aligner into the single Settings entry; `useModels.downloadBundle` fetches the missing parts one after another (the next starts on `model:complete`), and `hasReadyModel` needs both. `DPDFNET_MODEL_ID` is speech enhancement's clean-up (`useModels.enhanceModels` is `{ dpdfnet }`).
- **`utils/exportFormats.ts`** — TXT/SRT/VTT/JSON serializers.
- **`styles/global.scss`** — custom design layer over Carbon. **UI convention:** labels in the app are sentence case ("New project", "Speaker detection"); the menu bar keeps macOS's title case. Lengths are shown in the player's clock style everywhere (`lib/time.ts` `formatLength`: "1:37", "43:00"). Build from Carbon components (`Tabs`, `Tile`, `ContainedList`, `Accordion`, `IconButton`, `Tag`, `Toggle`, `ContentSwitcher`, `FormGroup`, `Select`, `ProgressBar`, `InlineNotification`, `Modal`, the preview `IconIndicator` for statuses) and style new parts with Carbon's `type`, `spacing` and `theme` Sass modules (`@use '@carbon/react/scss/…'`) rather than hard-coded values. The amber accent is `--wave-accent`: `wave-btn-accent` on primary buttons, and Carbon's `--cds-border-interactive` re-pointed to it where a selection should read as the accent (the inspector tabs). `<body>` carries `cds--g100` (index.html) because Carbon portals menus, overflow menus and tooltips into `<body>`, outside `<Theme>`. Progress is amber everywhere (`.cds--progress-bar` re-points `--cds-interactive`), and so are dialogs' primary buttons. **Labels and affordances:** every label says exactly what its control does, or what it sets: a switch is named for what it switches ("Use for playback and export", not "Play…"), a button that leads to another screen names that screen ("Settings →", not "Get"), and a verb button does that thing at once. Anything that opens another view shows it: a list row that opens a view has a chevron. A clickable item with no visible cue gets a hint that says what clicking does. Check every new control for both before shipping it. Word states (playing, selected, cut, corrected, …) live in one ordered section, *Words in the transcript*: the later rule wins, there's no `!important`, and nothing transitions (a highlight that fades as it moves from word to word flickers).

App navigation lives in `App.tsx`: a Projects/Settings shell, with the editor opening full-window (bypassing the sidebar) when a project is selected.

- **The open project** comes from the project list (`current`), so its status stays live: a project opened while transcribing loads its transcript when done (`useTranscript(id, ready)`).
- **App also handles:**
  - the shell's menu commands (⌘N sets `newProjectPending` for the Projects page);
  - drag and drop (`getCurrentWebview().onDragDropEvent`: each audio file becomes a project; `isAudioFile`, `AUDIO_EXTENSIONS`);
  - `retryProject` (transcribe again, or import again when the audio never arrived);
  - full screen (`body.wave-fullscreen` drops the window-button inset).
- **Window dragging:** the title bar is hidden, so the window is dragged by elements marked `data-tauri-drag-region`. Tauri checks only the element under the pointer, so plain children are marked too or ignore the pointer. They are the sidebar's logo row, `.wave-titlebar` (a sticky 28 px strip atop Projects and Settings), the page headers, and the editor top bar's empty parts. The editor title is left out: its double-click renames.
- **The Projects page:**
  - The empty state is a welcome (`FirstRun`): `BrandHero` (`components/brand/`), "Welcome to Wave", the three first-run steps in a row (`.wave-steps`: a rule over each turns green when done and amber when it's the current one), then one action (Set up transcription, or New Project once a model is ready). It fits the 960×600 minimum window.
  - `BrandHero` is Wave's idea as one loop, in Fraunces over its waveform: "So, editing audio is um just editing tax." A long pause is shortened (1.8 s → 0.4 s), "um" is drag-selected, ⌫'d, struck and cut, and the misheard "tax." is corrected (↩) to "text.". Each edit closes or opens the sentence from both sides, so it stays centred. A playhead then plays it, lighting each word amber, and three chips come in: Runs on your Mac, Private, Free.
  - It's SMIL on one 12 s clock (`T` holds the beats), laid out from word widths measured in Fraunces. Each word group's offset after each edit is precomputed (`move`), and the amber copy is drawn at the final positions behind a clip. Reduced motion gets the last frame. SMIL `keySplines` must stay within 0–1: an overshoot needs an extra keyframe.
  - Cards show a mini waveform (`CardWaveform`) and Transcribe / Transcribe again / Import again… when stuck.
  - The grid takes arrow keys, ↩ and ⌫ (`gridKeys`).
- **Contrast:** `--wave-text-muted` and `--wave-text-faint` keep 4.5:1, since both are used for text.

### Core concept — non-destructive editing

Deleting words, silences or a drawn waveform range appends an action to an in-memory edit queue (persisted to `edits.json`, keyed to the transcript by a text-only fingerprint so re-alignment keeps edits). Original audio is never mutated. `computeCutOps` (EditorPage, a pure function behind the `currentOps` memo) turns the actions into cut ranges: a run of adjacent deleted words is one cut, padded up to 60 ms into neighbouring gaps, and an edge that touches another word is eased to the quietest point nearby (`quietestPoint`). Dragging a cut's edge on the waveform records an `adjust` action that overrides that edge. A **correction** action (`EditAction.correction`: word index + text, no audio change) fixes a misheard word: `enrichedWords` is the transcribed words with the corrections applied (the latest per word wins; `correctedFrom` keeps what was heard), memoised on the corrections alone so other edits don't rebuild the transcript. The fingerprint stays on the transcribed text. `EditPlayer` plays the result gaplessly; at export Rust splices the same ranges with the same crossfade, so preview matches export.

**Dependency patch:** `patches/signalsmith-stretch@1.3.2.patch` (applied by bun via `patchedDependencies`) fixes the stretcher's read loop, which crashes the worklet once it holds more than one input buffer. Two other quirks are worked around in `editPlayer.ts`: `schedule()` drops *every* pending future change, and the node needs one input or it throws while idle. After changing the patch, delete `node_modules/.vite` so Vite re-bundles it.

### Background jobs — one status for everything that takes a while

`lib/activity.ts` holds every job: imports, transcription, model downloads, speaker detection, speech enhancement, re-alignment, audio export ("Reading the audio", then "Encoding MP3" from `export:progress`), and the editor's own loading (building `waveform.bin` for an old project, decoding the audio for playback). `ActivityStatus` shows the newest one: its `JobIcon` inside a progress ring (a turning arc when there's no telling), the label, the percentage and "+N" for more. It opens a Carbon `Popover` listing all of them with a `ProgressBar` each, Cancel where a job can stop (enhancement, downloads) and Dismiss for failures. A finished job shows its done label for 4 s; a failure stays until dismissed; `quietMs` keeps quick jobs from flickering. The Dock icon shows the average progress of the jobs that can measure it (`setProgressBar`, permission `core:window:allow-set-progress-bar`).

- Import, transcription and downloads are followed from their backend events (`useActivityEvents`). A bundle's parts download as one job (`finishSoon` waits for the next part).
- The AI tools start with `activity.track(...)` and read `running`/`progress` back from the store, so their panels show a run started before the editor was opened. `useActivityEnd` reloads what the job saved when it ends (or shows its error), whichever editor is open by then. A second Detect while one runs gets the same job.
- The tools' backend commands report progress only (`speakers:progress`, `enhance:progress` with its phase); they finish through the invoke's promise.

### Editor interactions — text for words, waveform for exact trims

The transcript edits whole words. The waveform exists for micro-adjustments the text can't make (the tail of a word a text cut left behind, a breath), so it is **exact**: what you drag is what you get.

- **One selection** (`selectionRange`, EditorPage) drives the waveform region, the transcript, and the word-lane chips. Marks: whole words inside get `--selected`; words it only touches get the dashed `--selected-part`.
- **Colour:** the played portion is never tinted (`progressColor = waveColor`). Colour marks only:
  - the selection (blue)
  - cuts (red)
  - a "Show in…" reference (purple)
  - the playhead (amber)
- **Drawing a selection** is our own handler in `useWaveform`, not the Regions plugin's drag selection, for two reasons:
  - The plugin starts every selection 5 px wide (~350 ms at 10× zoom).
  - It lets the browser start a text selection, which highlights the whole window in WebKit.

  A press that moves ≤ 3 px is a click (seek). The timeline is `user-select: none`, and a press there cancels `mousedown`. Region edges (selection and cuts) are still resized with the plugin's handles.
- **Snap to words** is an opt-in toolbar toggle, off by default and persisted in `localStorage`. When on, an edge within 6 px of a word edge lands on it; ⌥ places it freely.
- **Delete / ⌫ on a selection** (`cutSelectionRange`):
  - Exactly whole words (text selections, a double-clicked word, a snapped drag): deleted as words.
  - Anything else: cut **exactly as drawn** (a range cut). It never grows to the words it touches.
- **Range cuts show in the text:** a word they swallow reads as deleted (`--cutaudio`); a word they trim gets a wavy underline (`--partcut`).
- **Fine-tuning:** ⇧←/→ moves the selection's end, ⌥⇧←/→ its start (10 ms; ⌘ for 1 ms). The readout shows start – end (length) to the millisecond. Dragging a cut's edge records an `adjust` edit.
- **Right-click** (transcript, waveform or the word lane) opens a plain context menu and changes nothing by itself. Its first line names the target and its times. It opens at the pointer every time (a new key per right-click: Carbon places a menu only as it opens) and closes on a press, wheel or app switch outside it, since Carbon only closes when focus moves somewhere focusable. The WebView's own menu is suppressed everywhere but text fields and selected text (`main.tsx`). "Show in timeline" / "Show in transcript" are what outline the passage in the other view and bring it into view.
  - On the waveform the target is the cut under the pointer, else the selection (words if exact, otherwise a range), else the word, else the pause.
- **Zoom:**
  - Keyboard ± anchors on the pointer over the waveform, else the selection, else the playhead (`resolveAnchor`).
  - Z zooms to the selection or highlight, and pressing it again goes back. ⇧Z shows the whole file.
- **Playback:**
  - C previews a cut before making it: `playRange` with `extraCuts`, using exactly what Delete would cut.
  - Tab / ⇧Tab jump between cuts.
  - The view follows the playhead a page at a time and pauses while you scroll away.
- **Find (⌘F):** `FindBar` above the text.
  - Every match is marked with `--match` (yellow), and the current one is the selection, so ⌫ cuts it; the bar's Cut button cuts it and moves on.
  - ↩/⇧↩ or ⌘G/⇧⌘G step through matches, Esc closes, and reopening keeps the last search.
- **Undo and redo:**
  - `undoAction` moves what it removes (a whole agent group at once) onto `redoRef`. `redo` puts it back, and any new edit clears the stack.
  - `editActionsRef` is updated ahead of renders, so quick repeated ⌘Zs each count.
- **Word by word:** `[` / `]` select the previous or next word (from a whole-word selection, else the word at the playhead) and move the playhead; `{` / `}` add the previous or next word (`stepWord`). ⇧←/→ still fine-tune by milliseconds.
- **First time in the editor:** a dismissible hint above the text (`wave.hint.editor` in localStorage). The hint and the Find bar reach the memoised `EditorBody` as one memoised `banner`.
- **Correcting a word:** ↩ on a selection of exactly one word, or right-click → Correct word…, opens `WordCorrection` under the word (scrolled into view; Enter or clicking away saves, Esc cancels). It's an undoable edit (Edits list, ⌘Z). Corrected words get `--corrected` (a green bar and tint, never dimmed as low confidence) and the tooltip "Corrected from …"; right-click offers Back to "…", and typing the transcribed text again does the same. The correction flows to Segments, the word lane and every export.
- **Restoring:** `removeFromEdits` takes words, range cuts, filler spans (from earlier versions) and their edge nudges out of the edit queue.
- **Fillers** are words: transcription writes them (for English; about two thirds of them on a test meeting), so they're cut like any word, by hand or by an agent (`find_text`, `cut_words`). There's no separate filler detector since Uhm was removed for open-sourcing. Filler cuts saved by earlier versions (`EditAction.fillers`) still apply, and Restore cut takes them back.
- **Speakers** (Tools tab): detection is saved as time segments, so it survives re-alignment; words are assigned in the editor (`speakerLabels`, EditorPage). In Flow, a turn starts a paragraph and the paragraph where the speaker changes carries `data-speaker` / `data-speaker-index` (the `SpeakerTurns` TipTap extension), drawn by CSS `::before`, so labels are never text or selection. Segments split at turns and name the speaker where it changes. TXT, SRT and VTT exports carry the names (`ExportWord.speaker`; VTT as `<v Name>`). Effects that re-mark words after a doc rebuild depend on `speakerLabels` too.
  - **Merging** is non-destructive: `Speaker.mergedInto` (saved; carried over by Detect again). Segments are mapped to their root speaker (`rootSpeaker`) *before* words are assigned (`speakerOfWord`), so a word split between the two goes to the merged speaker; the panel lists merged speakers under their target with **Separate**.
  - **The waveform** shows who has the floor as a 3 px strip under the word chips (`speakerTurns`: a pause ≥ 1.5 s ends a turn).
  - **Everything one person said** (a speaker's ⋯ menu, or right-click a word): `wordSelection`, a set of word indices exclusive with `selectionRange` (a new range clears it, Esc clears it). Marked in the text and the word lane, other speakers' turns dimmed, a readout in the toolbar; ⌫ deletes them as one edit ("everything X said (N words)").
- **Speech enhancement** (Tools tab, `EnhancePanel`): one choice up front, the clean-up (Off or DPDFNet). DPDFNet is chosen when it's downloaded (`availableModels`); without it the tool still runs the EQ and loudness (the row says "Loudness only: the clean-up needs a download"), and choosing DPDFNet names the download and offers Open Settings. A run saved with Clear by an earlier version still plays and reads "Clear · …"; the next run starts from DPDFNet, so Apply changes shows at once. Then Enhance audio (or Apply changes) and `EnhancePreview`: 15 s from the selection or the playhead, original and enhanced playing together with an Original/Enhanced switch, the original loudness-matched. Under Options: Clean-up strength (Subtle/Medium/Full, only with the clean-up), Loudness (−19/−14/−23 LUFS or off). A run writes an enhanced copy next to the original; the switch (also on the tool's row) picks which version plays and exports, swapping in place mid-playback. Every combination stays sample-aligned with the original (`tests::stays_in_step`), so edits apply to both versions and switching mid-playback doesn't jump. Transcription and alignment always use the original.
- **EQ** (Tools tab, `EqPanel`): a preset, each named for the problem it fixes with a line on what it does (Clearer first, "a good place to start"), and Subtle/Medium/Strong. It isn't a separate pass: it shares Speech enhancement's draft and enhanced audio, between noise removal and the loudness target, so the view says what will run ("Runs: Clean-up with DPDFNet → EQ Clearer (medium) → loudness to −19 LUFS") with a link to Speech enhancement for the rest. Apply EQ (or Apply changes), the same 15 s preview, and the same switch once applied. Both rows show what's applied.
  - Tools rows: Carbon floats a list item's action over the row, so `RowActions` measures the row's action and chevron (`--wave-tools-actions`) and the text stops short of them; a status wraps to two lines rather than being cut.
- **Pauses** (Tools tab, `PausesPanel`, `lib/pauses.ts`):
  - `findPauses` reads the pauses between kept words from the transcript, skipping any an edit has touched. A word ending a sentence, or a change of speaker, makes a pause "between sentences".
  - A rhythm (Tight/Natural/Relaxed, saved as `wave.pauseRhythm`) caps pauses between and within sentences. `shortenPauses` cuts each longer pause from its middle.
  - Preview plays 20 s from the next long pause after the playhead, with those cuts (`playRange` + `extraCuts`). Shorten makes them as one group (a user `EditAction.group` without an agent), undone together.
  - **Adding a pause** (`EditAction.insert`): right-click a word → Add pause after (0.25–2 s; it goes in the middle of the gap to the next word), or Add at playhead. It's filled with room tone: `findRoomTone` picks the quietest 400 ms between words within 15 s.
  - In the text it's a green `+0.5 s` token (`TextToken`, id `p` + the edit's id). Right-click it to take it out. On the waveform it's a green marker.
  - The player (`EditPlayer.setInserts`) and the exporter (`InsertOp`, `splice` in projects.rs) both place a pause that falls inside a cut at the cut's join, and crossfade it like any join. While one plays, `currentTime` holds where it was added.
- **Exports on the edited timeline:** TXT/SRT/VTT/JSON times are mapped by `editedTime` (cuts before a word taken off, pauses added before it put on), so subtitles match the exported audio.

### AI agents (MCP) — editing through Claude or ChatGPT

Agent apps launch `<this executable> mcp` (Claude Desktop's `claude_desktop_config.json`, `claude mcp add`, `codex mcp add`, ChatGPT desktop's MCP servers settings). Each tool call goes from `mcp.rs` through `agent.rs`'s socket to `useAgentBridge` and `runTool`, which works through the open editor's `EditorAgentApi`, opening the project first if needed (`App` keys `EditorPage` by project). The edit logic is the editor's own, so nothing is duplicated in Rust: edits appear live and undo like the user's.

- **Word numbers** are transcript positions; the editor maps them to `enrichedWords` indices, which include pause markers.
- **Grouping:** everything one call does is one group (`EditAction.group` with label and agent). `newAction` tags edits made while `agentGroupRef` is set. Undo, ⌘Z and the Edits list treat a group as one edit, tagged with the agent's name.
- **Visibility:** each editing call also flashes in the activity status (`activity.announce`).
- **Long jobs** (`analyze`) start and return at once.
- **Exporting audio** (`export_audio`): a `format`, a preset id ("mp3-192") or a format at its standard preset ("flac"); MP3 at 128 kbps when left out, as in the Export tab. The file goes to Downloads with the format's extension.
- **Adding a tool:** add it to `tools()` in `mcp.rs` and to `TOOLS` in `agentTools.ts`, plus an `EditorAgentApi` method if it needs editor state.

## Adding a Tauri command

1. Define it in the relevant `src-tauri/src/*.rs` module with `#[tauri::command]`.
2. Register it in `lib.rs` under `.invoke_handler(tauri::generate_handler![...])`.
3. Call it from the frontend with `invoke("command_name", { camelCaseArg })`.

## Key config files

- `src-tauri/tauri.conf.json` — `productName` "Wave", `version` read from `../package.json` (the one place the version lives; the frontend imports it as `APP_VERSION` from `lib/appInfo.ts`; keep `Cargo.toml`'s in step), the overlay title bar (`titleBarStyle`, `hiddenTitle`); also window, identifier, bundle targets, CSP, asset protocol scope (`$APPDATA/**`, `$HOME/**`). The window starts **hidden** with a dark `backgroundColor` and `theme`. `App` shows it from its first effect, not on a frame, since a hidden window gets no frames. `lib.rs` shows it after 8 s if the frontend never does. `macOSPrivateApi` (with Cargo's `macos-private-api` feature) stops the WebView painting its own white background, so anything not yet drawn is dark; it's a private API, which the Mac App Store rejects. `index.html` paints the background inline before any script or style loads.
- `src-tauri/icons/` — the app icon. `app-icon.png` is the 1024 px master on Apple's macOS grid: an 824 px squircle tile (a superellipse, n = 5) centred with 100 px margins, opaque inside, and a soft shadow (10 px down, 35 % black). `icon.icns` holds all ten macOS sizes (16–512 pt at 1× and 2×; the 16–64 px ones lightly sharpened). It was made with `iconutil` from that master. The other files are what `bunx tauri icon` makes from it (Android and iOS sets left out). Regenerate them from the master, but keep `icon.icns` from the iconset. `tauri dev` runs the bare binary, whose Dock icon is a copy of `icon.icns` compiled in, so `build.rs` watches `icons/` (Cargo wouldn't otherwise rebuild for an icon change).
- `src-tauri/capabilities/default.json` — Tauri capability/permission definitions (including the Dock progress bar).
- `src-tauri/.cargo/config.toml` — `MACOSX_DEPLOYMENT_TARGET = "13.4"`, so whisper.cpp (built by CMake) targets the same oldest macOS as ONNX Runtime and `bundle.macOS.minimumSystemVersion`. Without it, CMake targets the macOS doing the build.
- `src-tauri/Cargo.toml` — Rust dependencies (whisper-rs, ort, symphonia, rubato, hound, reqwest, tokio, …). `ort` is pinned (`=2.0.0-rc.13`) and downloads a prebuilt ONNX Runtime at build time.
- `patches/` — bun dependency patches (see "Dependency patch" above).
- `src-tauri/vendor/lame/` — LAME for MP3 export: `libmp3lame.0.dylib` (arm64, macOS 13.4, encoder only, install name `@rpath/…`, ad-hoc signed), `build.sh` (downloads or takes `lame-3.100.tar.gz`, checks the SHA-256 Homebrew pins, drops `lame_init_old` and the decoder's functions from the export list, builds, renames, re-signs), `COPYING` (LGPL), `LICENSE`, and `README.md` (the notice). `tauri.conf.json` bundles the library through `bundle.macOS.frameworks` and the notice and licence through `bundle.resources` (`Resources/licenses/`). Whoever distributes Wave should offer LAME's source alongside it.
